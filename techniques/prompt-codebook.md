# 프롬프트 코드북

## 요약

열 이름을 1자로, 열거형 값을 정수로 바꾸는 **코드표를 프롬프트에 선언**하고 그 표기로 받는다. 헤더 TSV 대비 **−60.5%**, 96칸 정확도 **1.0**.

코드표가 프롬프트를 329자 늘리고 출력에서 378자를 아끼므로 손익분기 `R* = 1` — 문자 총합 회계에서도 **첫 요청에 회수된다.**

## 적용법

출력 형식 지시 아래에 대응표를 통째로 적는다. 모델이 대응을 추측하지 않고 베끼게 하는 것이 핵심이다.

```
열 이름과 값은 아래 코드표대로 줄여서 씁니다.

열 이름: asset_id=a, region=r, env=e, role=o, os=s, tier=t, cpu=c, status=u
열 순서: a, r, e, o, s, t, c, u
a: `AS-` 접두사를 떼고 숫자만 (AS-2001 -> 2001)
r: apne1=1, apne2=2, usea1=3, euwe1=4
e: prod=1, stage=2, dev=3
...
c: 숫자를 그대로 씁니다
```

**손익분기 계산.** `R* = ceil(ΔP / ΔO)` — `ΔP`는 코드표가 프롬프트에 더한 길이, `ΔO`는 요청당 출력 절감. 같은 스키마를 `R*` 번 이상 쓸 거면 총합 회계에서도 이득이다. **출력 토큰만 세는 회계에서는 `R*`가 필요 없다** — 언제나 이득이다.

**쓸 조건.**

| 조건 | 이유 |
|---|---|
| 받는 쪽이 **코드**다 | `2003 3 3 3 2 3 4 3`은 코드표 없이 읽히지 않는다 |
| 값이 **닫힌 집합**이다 | 자유 문자열은 코드화할 수 없다 |
| 대응표를 **전부 적어줄 수 있다** | 적어주지 않고 짧은 키만 요구하는 것은 다른 기법이고 정확도가 다르다 |

## 한계

- **"1자 키가 안전하다"는 근거가 아니다.** 정확도가 유지된 것은 코드표를 전부 적어줬기 때문이다. 설명 없이 축약 키만 요구하는 조건(A2-H2)은 여전히 미판정이며, 이 결과를 그 근거로 인용하면 안 된다.
- **`R* = 1`은 문자 수 회계다.** 입력 토큰과 출력 토큰은 단가가 다르다. 실제 비용에서는 출력이 비싸므로 더 유리해지겠지만 이 환경에서 확인할 수 없다. **두 회계를 하나의 절감률로 합쳐 보고하지 않는다.**
- 프롬프트 캐싱이 걸리면 `ΔP`의 실질 비용은 더 내려간다. 측정하지 않았다.
- 사람이 읽어야 하는 산출물에는 쓸 수 없다.
- 수치는 **문자 수 proxy**다. 정수 코드는 토크나이저가 이미 1토큰으로 처리할 가능성이 높아 실제 토큰 절감은 −60.5%보다 작을 수 있다 (A6-H7, 미판정).
- 값 어휘 하나(리전·환경·역할·OS·등급·상태)에서만 쟀다.
