# 범위 제한 지시

## 요약

⚠️ **근거가 약한 기법이다.** 사전등록 기준으로는 채택됐지만 절감이 −6.2%로 동률 구간(±5%)을 간신히 넘겼고 **조건 간 분포가 겹친다.** 부호만 신뢰하고 크기는 신뢰하지 않는다.

코딩 에이전트에게 `요청한 것만 만듭니다. 파일·함수·테스트는 통과에 필요한 만큼만 더합니다.` 한 줄을 넣으면 코드 변경분이 **−6.2%**, 테스트 통과율은 9/9 유지.

가설의 나머지 절반("미요청 산출물 개수를 줄인다")은 **판정 불가**다 — 기준 조건에서도 새 파일이 하나도 생기지 않아 걷어낼 것이 없었다.

## 적용법

```
요청한 것만 만듭니다. 파일·함수·테스트는 통과에 필요한 만큼만 더합니다.
```

**쓸 조건.** 하나라도 어긋나면 효과를 기대하지 않는다.

| 조건 | 이유 |
|---|---|
| 요구사항이 **모호**하거나 확장 여지가 있다 | 명세가 테스트로 딱 떨어지면 기준 조건부터 범위를 넘지 않는다(실측이 그랬다) |
| 산출물이 **여러 파일**에 걸칠 수 있다 | 파일 하나짜리 과제에서는 잴 것이 없다 |
| 통과 기준이 **명시**돼 있다 | "필요한 만큼"의 기준이 없으면 지시가 모호해진다 |

**먼저 기준 조건을 재본다.** 지시 없이 돌렸을 때 미요청 산출물이 0개라면 이 지시는 걸 자리가 없다. 라운드 6이 그 경우였다.

## 측정 결과

| 조건 A | 조건 B | 시행 | 단위 | 결과 |
|---|---|---|---|---|
| 지시 없음 | **범위 제한** | 각 n=3 | 코드 변경분 문자 수 (proxy) | **−6.2%** (931 → 874) |
| 지시 없음 | 범위 제한 | 각 n=3 | 새로 생긴 파일 개수 | **0 → 0** (판정 불가) |
| 품질 | 양 조건 | `node --test` | 통과 수 | **9/9 vs 9/9** |

## 함께 쓸 때 — 하위가산성

같은 라운드에서 이 지시를 요약 규칙(`final-summary-cap.md`)·주석 규칙과 함께 걸어 봤다.

| | 총출력 절감 |
|---|---|
| 요약 규칙 단독 | 253자 |
| 범위 제한 단독 | 184자 |
| 주석 규칙 단독 | 104자 |
| **개별 합** | **540자** |
| **셋 다 걸었을 때** | **349자 (합의 64.6%)** |

**억제 지시의 절감률을 서로 더하지 않는다.** 라운드 1에서 하네스 차단으로 판정 불가가 됐던 A5-H7이 여기서 확인됐고, 라운드 4의 지시 사다리(한계 절감 1,681 → 292 → 165자)와 같은 방향이다.

## 한계

1. **−6.2%는 부호만 신뢰한다.** 평균 차 57자는 조건 내 표준편차(31·44자)와 같은 자릿수다. n=3에서 크기를 주장할 검정력이 없다.
2. **가설의 절반이 미검정.** `extra`(미요청 산출물)의 기준값이 0이라 바닥 효과다. 범위를 넘칠 유인이 있는 과제로 재측정이 필요하다 — 라운드 7 이월.
3. **문자 수는 토큰이 아니다.** 코드 변경분은 파일에 남은 것만 세므로 생성량의 하한이다.
4. **주석 규칙은 같은 실험에서 기각됐다.** `설명은 코드 이름으로 합니다. 주석 없이 읽히게 씁니다.` 는 잴 수 없었다 — 15시행 전부 주석을 한 글자도 더하지 않았기 때문이다(원본 138자 그대로). **주석이 실제로 붙는 과제인지 먼저 확인하고 걸 것.**
5. **하위가산성 64.6%는 이 조합 한 건의 관측이다.** 세 처치 중 하나(주석)가 표적에 걸리지 않았으므로 "겹치지 않는 세 레버"의 값이 아니다.
6. 과제 1종(JS 기능 추가), 규모 1종(41줄 모듈)에서만 쟀다.
