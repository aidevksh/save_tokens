# 예시는 원하는 분량으로 쓴다

## 요약

프롬프트에 붙이는 **예시 답변의 길이가 산출물 길이를 끌어당긴다.** 148자짜리 짧은 예시 하나를 붙이면 예시 없을 때 대비 **−82.7%**, 같은 내용을 805자로 늘려 붙이면 −25.4%에 그친다. 요구 항목 커버리지는 세 조건 모두 만점.

**말로 시키는 것보다 세다.** 같은 과제에서 48자 긍정형 간결성 지시가 −69.3%였는데(`positive-conciseness-instruction.md`), 148자 예시 하나가 −82.7%를 냈다.

## 적용법

과제 명세 뒤, 꼬리 지시 앞에 **다른 주제**의 예시를 하나 붙인다.

```
참고로, 다른 명세를 같은 형식으로 설명한 문서는 다음과 같습니다.

---
로그 보존 정책은 다음과 같다. 보존 기간은 30일이다. 30일이 지난 로그는 자동으로 삭제된다.
저장 위치는 객체 스토리지다. 압축은 gzip을 쓴다. 조회는 관리 콘솔에서 한다.
---
```

**세 가지를 지킨다.**

| 규칙 | 이유 |
|---|---|
| **원하는 분량으로 쓴다** | 예시가 곧 길이 지시다. 잘 쓴 긴 문서를 붙이면 산출물도 그만큼 길어진다 |
| **다른 주제로 쓴다** | 같은 주제면 베끼는 것이 답이 되어 과제가 무너진다 |
| **원하는 형식으로 쓴다** | 제목·목록·문단 구조까지 그대로 따라온다 |

**분량 잡는 법.** 관측된 배율은 산출물 ≈ 예시의 **2.2~2.8배**다. 800자짜리 답을 원하면 예시를 300자 안팎으로 쓴다. 이 배율은 재료 하나·길이 두 점에서 나온 관측이므로 **출발점으로만** 쓰고 한 번 재본 뒤 조정한다.

## 측정 결과

| 조건 A | 조건 B | 시행 | 단위 | 결과 |
|---|---|---|---|---|
| 예시 없음 | **짧은 예시 148자** | 각 n=3 | 산출물 문자 수 (proxy) | **−82.7%** (2,425 → 419) |
| 예시 없음 | 긴 예시 805자 | 각 n=3 | 산출물 문자 수 (proxy) | −25.4% (2,425 → 1,810) |
| 긴 예시 | **짧은 예시** | 각 n=3 | 산출물 문자 수 (proxy) | **−76.9%** (1,810 → 419) |
| 품질 | 명세 6항목 커버리지 | | 0–6 | **세 조건 모두 6.0** (만점) |

라운드 5, 요청 제한 명세 6항목 → 신입 개발자용 한국어 설명 문서. 두 예시는 같은 사실 5개를 담고 길이만 5.4배 다르다. 조건 내 표준편차: 짧은 예시 80자 / 긴 예시 127자 / 예시 없음 308자. 상세: `experiments/round5-results.md` §5, 해설: `explainers/r5-a1h5-example-length-anchor.html`.

예시 길이가 5.4배 늘자 산출물이 **4.3배** 늘었다. 두 조건 모두 산출물이 예시의 2.2~2.8배에 자리 잡았다.

## 한계

- **예시 길이와 예시 구조를 분리하지 못했다.** 긴 예시에는 제목·번호 절이 함께 들어갔고 산출물도 그 구조를 모방했다. 순수 길이 효과만 떼려면 구조를 고정한 대조군이 필요하다 — 라운드 6 이월.
- **2.2~2.8배는 법칙이 아니라 관측이다.** 재료 하나, 길이 두 점에서 나왔다.
- **기준 조건이 이미 오염돼 있다 → −82.7%는 하한.** 피험자가 저장소 `CLAUDE.md`의 억제 규칙("결론부터, 서론·자평 금지")을 물고 시작한다.
- 수치는 전부 **문자 수 proxy**다. 토큰 절감률이 아니다 (A6-H7, 미판정).
- 산문 설명 문서 1종·한국어 1종에서만 쟀다. 코드·표 산출물에는 적용하지 않았다.
- 품질 게이트는 6항목의 **존재**만 본다. 419자 문서와 2,425자 문서의 서술 깊이 차이는 측정하지 않았다 — "커버리지 만점"이 "품질 동일"을 뜻하지 않는다.
