# 표 형태 페이로드는 전체 키 JSON 대신 헤더 TSV로 받는다

## 요약

동일 레코드 집합을 **레코드마다 키를 반복하는 JSON 객체 배열**로 받는 대신 **헤더 1줄 + 행 N줄의 TSV**로 받으면 산출물 문자 수가 크게 줄고, 이번 측정에서 셀 정확도 손실은 없었다.

절감의 출처는 명확하다: JSON 객체 배열은 **키 이름을 레코드 수만큼 반복**한다. 이번 과제(12레코드 × 8필드)에서 JSON 초과분 1297자 중 **1032자(79.6%)가 반복된 키 이름·따옴표·콜론**이었고, TSV는 그것을 62자짜리 헤더 1줄로 대체한다. 따라서 **절감폭은 레코드 수에 비례해 커지고, 필드 값이 길어질수록 상대적으로 작아진다.**

## 적용법

레코드 수 ≥ 약 5, 필드가 고정 스키마, 값에 탭·줄바꿈이 없는 표 형태 페이로드에 적용한다.

프롬프트의 출력 형식 지정을 다음처럼 바꾼다 (실측에 사용한 문구 그대로):

```
출력 형식: 결과를 TSV로 <경로> 에 저장하세요. 첫 줄은 헤더이고, 그 아래 레코드 1건당 1줄씩
총 N줄입니다. 헤더와 데이터 행 모두 열 구분자는 탭 문자 1개이며 열 순서는 다음과 같습니다.
<필드1>, <필드2>, ...
```

- **열 순서를 명시한다.** 헤더만 요구하면 순서가 흔들려 후처리가 깨진다.
- **행 수를 명시한다** (`총 N줄`). 누락 검출이 파싱 단계에서 가능해진다.
- 값 대응표(enum 허용값)는 JSON 조건과 동일하게 유지한다. 형식만 바꾸고 어휘는 바꾸지 않는다.
- 이 처치는 **출력 형식 지정 문단만** 바꾸므로 프롬프트 나머지와 직교한다.

**적용하면 안 되는 경우**
- 중첩 구조·가변 필드·배열 값이 있는 페이로드 (TSV로 표현 불가)
- 값에 탭이나 줄바꿈이 포함될 수 있는 경우 (이스케이프 규약이 필요해지고 그 순간 이점이 사라진다)
- 레코드가 1~2건 (헤더 고정비가 절감을 잡아먹는다)
- 소비자가 JSON 스키마 검증을 요구하는 경우

### 경계 — 마크다운 표는 TSV와 JSON 사이에 있다

라운드 3(A2-H6)에서 **같은 과제·같은 정답 키**로 마크다운 표 조건을 추가했다. 세 형식 모두 96셀 정확도 1.0.

| 형식 | `chars` | JSON 대비 | TSV 대비 |
|---|---|---|---|
| 전체 키 JSON | 2,093 | — | +181.3% |
| **마크다운 표** | **1,028** | **−50.9%** | **+38.2%** |
| 헤더 TSV | 744 | −64.5% | — |

마크다운 표 오버헤드는 항등식으로 분해된다 (8열 기준, 오차 0):

```
L_MD − L_TSV = 18 × (레코드 수 + 1) + 50
```

행당 18자는 구분자 차이(`| ` + `" | "`×7 + ` |` = 25자 대 탭 7개 = 7자), 50은 구분 행(`| --- | … |`)이다. **레코드당 고정비라서 레코드 수에 선형으로 커진다** — 반복 단위가 JSON의 키 이름에서 파이프·공백으로 바뀐 것뿐이고 구조는 같다. 역으로 셀이 길어지면 상대 오버헤드는 줄어든다(이 과제의 셀은 평균 8.5자).

**함의**: 소비자가 사람이라 표 렌더링이 필요하면 마크다운 표가 JSON보다 절반 짧으므로 충분히 쓸 만하다. 그러나 소비자가 코드라면 TSV가 계속 정답이다 — 파이프와 정렬 공백은 파서에게 아무 정보도 주지 않는다.

출처: `experiments/round3-plan.md` §6 P6·P7 사전등록 → `experiments/round3-results.md` §2 **채택**. 시행 T·M 각 n=2, **조건 내 분산 0(바이트 동일)**.

## 경계 — 레코드 수를 바꾸면 (라운드 5)

레코드 수만 3 / 12 / 24로 바꾸고 반복률을 0.195로 고정해 다시 쟀다.

| `N` | JSON | TSV | 절감량 `D` | 절감률 |
|---|---|---|---|---|
| 3 | 537 | 188 | 349 | 65.0% |
| 12 | 1,712 | 625 | 1,087 | 63.5% |
| 24 | 3,223 | 1,212 | 2,011 | **62.4%** |

`(라운드5 실측, proxy, 조건당 n=2)` 셀 정확도 여섯 조건 모두 1.0.

**절감의 절대량은 레코드 수에 거의 완벽히 비례한다** — `D ≈ 79.0N + 122`, **R² = 0.9997**. 위 §측정 결과의 "절감의 79.6%가 반복 키"가 여기서 **레코드당 79.0자**로 못 박힌다.

**그런데 절감률은 커지지 않고 미세하게 줄어든다.** 두 형식을 따로 적합하면 이유가 보인다.

| 형식 | 레코드당 | 고정비 |
|---|---|---|
| JSON | 127.9자 | 153.3자 |
| TSV | 48.8자 | 41.7자 |

JSON의 고정비가 TSV보다 111.6자 크다. 그래서 `N`이 작을수록 JSON이 상대적으로 더 손해이고, `N`이 커지면 절감률이 레코드당 비율 `1 − 48.8/127.9 = 61.8%`로 **위에서 수렴**한다.

→ **"레코드가 많으니 TSV로 바꾸면 절감률이 더 좋아진다"는 틀렸다.** 절감률은 처음부터 62% 근처이고, 커지는 것은 절감의 절대량이다. 레코드 100건이면 약 8,000자, 1,000건이면 약 79,000자.

이로써 아래 한계 8("레코드 수 선형성은 유도했을 뿐 검정하지 않았다")이 해소된다. 다만 검정된 것은 **JSON↔TSV 절감량의 선형성**이고, 마크다운 표 항등식 `18(N+1)+50`은 여전히 N=12 한 점의 사후 항등식이다.

## 한계

1. **문자 수는 토큰이 아니다. −65.9%는 토큰 절감률의 상한으로 읽어야 한다.** 어긋나는 이유가 최소 세 개이고 전부 같은 방향(과대평가)을 가리킨다: (a) JSON의 반복 키(`"ticket_id": `)는 코퍼스에 흔해 소수 토큰으로 병합될 가능성이 높다, (b) TSV의 탭 91개는 `chars_nows`에서 0으로 계산되지만 토큰으로는 0이 아니다, (c) 탭으로 끊긴 짧은 토막의 나열은 문자당 토큰 수가 올라갈 수 있다. 실제 토큰 절감률은 `usage.output_tokens` 없이 **원리적으로 확인 불가**다.
2. **절감률을 다른 형상에 그대로 옮길 수 없다.** 절감의 79.6%가 반복 키에서 나오므로, 레코드가 적거나 필드 값이 길면 절감률이 급격히 낮아진다. 레코드 수 종속성은 미측정(축2 H8, 라운드 2 이월).
3. **조건 내 분산 0 = 반복 없음.** n=4로 적었지만 4개 산출물이 바이트 동일하므로 통계적 검정력은 n=1과 같다. 얻은 것은 "이 프롬프트에서 출력이 결정적"이라는 사실뿐이며, 좁은 재현성을 넓은 외적 타당도로 오독하면 안 된다.
4. **thinking 토큰 미측정.** 산출물 파일만 쟀다. TSV로 표를 짜맞추는 사고량이 JSON보다 많았다면 이 수치는 절감을 과대평가한다. 확인 수단은 `usage.output_tokens_details.thinking_tokens` 뿐이다.
5. **오염 조건 병기.** 조건 A·B 모두 이 저장소 `CLAUDE.md`의 억제 규칙이 걸린 Claude Code 세션에서 측정했다. 다만 조작 변수(직렬화 형식)가 그 규칙과 직교하고 지시 위반이 0건이라 차분은 유효하다고 판단했다. 일반 API 사용자 환경으로의 외삽은 미검증.
6. **모델 세대 간 이식 불가.** 토크나이저 세대 차 때문에 다른 세대와 문자 수 비율을 직접 비교하지 않는다.
7. **마크다운 표까지는 비교했지만 "TSV가 최선"은 여전히 미확정.** 위 경계 절에서 `TSV < 마크다운 표 < JSON` 순서를 확인했다. 그러나 헤더 없는 positional 출력·키 축약·enum 코드화는 **proxy로 재면 안 되는 조작**이라(영문 단어를 숫자로 바꿔 문자↔토큰 비율이 깨진다) 아직 비교 대상에 넣지 못했다. 토큰 계측 확보 후 재개(축2 H2·H3·H5).
8. **레코드 수 선형성은 유도했을 뿐 검정하지 않았다.** 항등식 `18(N+1)+50`은 N=12 한 점에서 오차 0으로 맞았지만, 그것은 방출된 산출물과의 사후 항등식이다. 라운드 2에서 `N* ≈ 2m+C+k+2`가 같은 성질(사후 항등식이지만 사전 예측기로는 7.6~18.1% 과소추정)을 보였으므로 **N을 바꿔 직접 재기 전까지 예측기로 쓰지 않는다**(축2 H8, 라운드 4 이월). 열 수 일반화 `2×(열수−1)+4`도 미검증.
