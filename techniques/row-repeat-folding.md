# 행 방향 반복 접기 (`^`)

## 요약

표 형태 산출물에서 **바로 윗줄과 값이 같은 칸을 `^` 한 글자로 접게** 한다. 반복이 많은 표에서 헤더 TSV 대비 **−37.8%**, 셀 정확도 손실 0.

`techniques/tabular-payload-tsv-over-json.md`(JSON→TSV)가 **열 방향** 반복(반복되는 키 이름)을 걷어낸 기법이라면, 이것은 남은 **행 방향** 반복을 걷어낸다. 둘은 서로 다른 잉여를 겨냥하므로 함께 쓸 수 있다.

## 적용법

TSV 형식 지시에 두 문장을 덧붙인다.

```
바로 윗줄과 값이 같은 칸은 값 대신 `^` 한 글자만 씁니다. 첫 데이터 줄에는 `^` 를 쓰지
않습니다. 값이 다른 칸에는 값을 그대로 씁니다.
```

받는 쪽은 위에서 아래로 훑으며 `^`를 직전 행의 같은 열 값으로 치환한다. 8줄이면 된다.

```python
def unfold(rows):
    out = []
    for row in rows:
        out.append([out[-1][j] if v == "^" and out else v for j, v in enumerate(row)])
    return out
```

**쓸 조건 세 가지.** 하나라도 어긋나면 쓰지 않는다.

| 조건 | 이유 |
|---|---|
| 받는 쪽이 **코드**다 | `^`가 깔린 표는 사람이 훑을 수 없다. 실제 값을 알려면 위로 거슬러 올라가야 한다 |
| 값이 줄마다 **반복된다** | 반복이 0이면 이득도 0이다 |
| 값이 **한 글자보다 길다** | `^`도 한 글자다. 1자 값은 접어도 이득이 없다 |

## 측정 결과

| 조건 A | 조건 B | 시행 | 단위 | 결과 |
|---|---|---|---|---|
| 헤더 TSV (반복률 0.805) | **접기** | 각 n=2, 조건 내 분산 0 | 산출물 문자 수 (proxy) | **−37.8%** (629 → 391) |
| 헤더 TSV (반복률 0.195) | **접기** | 각 n=2, 조건 내 분산 0 | 산출물 문자 수 (proxy) | **−9.3%** (625 → 567) |
| 셀 정확도 | 두 반복률 모두 | 96칸 대조 | 정확도 | **1.0 / 1.0** (손실 0) |

라운드 4, 12레코드 × 8필드. 반복률은 재료 생성기가 정확히 15/77칸, 62/77칸으로 고정했다. 상세: `experiments/round4-results.md` §3, 해설: `explainers/r4-a6h4-row-repeat-folding.html`.

**절감폭은 접힌 칸 수 × 접힌 값의 평균 길이 −1** 로 계산된다. 저반복 조건에서 15칸을 접어 58자를 아꼈으므로 칸당 3.87자다. 이 계수는 어휘 길이에 따라 달라진다.

**방출 오버헤드 `H` = 0.** 네 조건 전부 산출물이 정답 키를 그 형식으로 낸 최소 텍스트와 길이가 정확히 같았다. 모델이 형식 지시를 그대로 지켰고 군더더기를 붙이지 않았다.

## 한계

- **손익분기는 출력이 아니라 프롬프트에 있다.** 접기 지시가 프롬프트를 **+83자** 늘린다. 반복률 0.195에서 아끼는 58자보다 크므로 **총합 회계에서는 순손실**이다. 출력 토큰만 세면 언제나 이득이고, 총비용을 따질 때만 이 83자를 얹는다.
- **예측했던 역전(반복이 적으면 접기가 더 길어진다)은 관측되지 않았다.** 규칙이 프롬프트에 있고 산출물에는 없어서 출력 회계에서는 원리적으로 지기 어렵다. 다만 반복률 0.195보다 낮은 구간은 재지 않았으므로 "역전 없음"을 일반 명제로 주장하지 않는다.
- 반복률 두 점(0.195, 0.805)만 봤다. 그 사이 곡선의 모양은 모른다.
- 수치는 전부 **문자 수 proxy**다. `^`와 탭은 토크나이저가 이미 싸게 처리할 수 있어 실제 토큰 절감은 −37.8%보다 작을 수 있다 (A6-H7, 미판정).
- 12레코드 × 8필드 한 형상에서만 쟀다. 레코드 수 종속성은 A2-H8로 여전히 미판정.
