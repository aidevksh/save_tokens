# 라운드 6 사전등록 — 미검증 가설 4건 (축 5 요인 분해 + 수치 상한)

작성 시각: 데이터 수집 **전**. §6 판정 기준은 실행 후 변경하지 않는다.

축 5(코딩 에이전트)는 7건 중 **6건이 미검증**이고 하나(A5-H2)는 라운드 3에서 기각됐다. 라운드 1에서 억제 지시를 **묶음**으로 시험했다가 하네스 차단으로 판정 불가가 된 A5-H7의 원래 자리이기도 하다. 이번 라운드는 그 묶음을 풀어 요인 하나씩 본다.

| 가설 | 축 | 주장 |
|---|---|---|
| **A5-H3** 마지막 요약 규칙 | 5 | 요약 규칙이 최종 응답 문자 수를 줄이고 완수도는 유지된다 |
| **A5-H4** 범위 제한 지시 | 5 | 범위 제한이 코드 줄 수와 미요청 산출물 개수를 줄이고 통과율은 유지된다 |
| **A5-H5** 주석 밀도 규칙 | 5 | 주석 규칙이 생성 코드의 주석 밀도를 낮추고 테스트 통과율은 유지된다 |
| **A1-H3** 수치 상한 | 1 | 수치 상한은 더 크게 줄이지만 요구사항 충족도가 하락한다 |

**A5-H7**(억제 지시 하위가산성)은 판정 불가 상태라 이번 4건에 넣지 않았다. 다만 세 처치를 모두 건 `ALL` 조건이 있으므로 **추가 시행 없이 재판정할 수 있다** — §6에 예측을 함께 사전등록한다.

## 1. 설계

과제 2개, 조건 9개, **신규 21시행** + 라운드 4 재사용 6시행.

프롬프트 전문은 `experiments/prompts/r6-*.txt`. 생성기 `experiments/scripts/gen_r6.py`가 다음을 검증한다 — 실패하면 파일을 쓰지 않는다.

- 각 과제 안에서 처치 줄을 뺀 공통부가 바이트 동일
- `r6-C0.txt` == `r4-K0.txt` (sha1 `d807c63774cc`), `r6-CK.txt` == `r4-K1.txt` (sha1 `1772fcc5e03d`)

### 과제 T9 — 기능 추가 코딩 루프 (A5-H3 / A5-H4 / A5-H5 / A5-H7)

`experiments/fixtures/task-c-feature`를 시행 디렉터리로 복사. `node --test` 9개 중 **5개 실패** 상태에서 시작한다(`complete()` 미구현, `list()`의 status 필터 미구현).

버그 수정이 아니라 **기능 추가**를 고른 이유: 범위를 넘칠 여지(추가 헬퍼·추가 테스트·README)와 주석을 달 여지가 있어야 세 처치가 각각 작용할 수 있다.

| 조건 | 처치 | 시행 |
|---|---|---|
| **B** | 없음 | t01, t08, t15 |
| **S3** | `마지막 보고는 무엇을 바꿨는지 세 줄 이내로 씁니다.` | t03, t09, t16 |
| **S4** | `요청한 것만 만듭니다. 파일·함수·테스트는 통과에 필요한 만큼만 더합니다.` | t04, t11, t18 |
| **S5** | `설명은 코드 이름으로 합니다. 주석 없이 읽히게 씁니다.` | t06, t12, t19 |
| **ALL** | 위 세 줄 전부 | t07, t13, t20 |

세 처치는 각각 **다른 팽창원**을 겨냥한다: 대화 보고문(S3), 산출물 범위(S4), 코드 주석(S5). 그래서 서로 다른 지표로 잰다.

## 2. 피험자 프롬프트

전 조건 공통 꼬리(조작 변수 아님):
> 도구 호출이 거부되면 다른 수단으로 우회하지 말고, 거부되었다는 사실을 보고하고 중단합니다.

**naive 유지**: 토큰·길이·실험·조건을 언급하지 않는다(T10의 상한 수치는 처치 자체이므로 예외). 시행 디렉터리는 저장소 밖(scratchpad). 전 시행 동일한 서브에이전트 유형(`general-purpose`)과 모델을 쓴다.

## 3. 종속 변수

| 기호 | 정의 | 측정 |
|---|---|---|
| `L_report` | 피험자 최종 대화 보고 문자 수 **(proxy)** — A5-H3 주 지표 | 오케스트레이터가 `report.txt`로 기록 |
| `L_diff` | 원본 대비 최종 `todo.js`의 `difflib` unified diff(C=3) 문자 수 — A5-H4 주 지표 | `score_r6.py` |
| `extra` | 시행 디렉터리에 새로 생긴 파일 개수(`todo.js`·`todo.test.js`·`report.txt` 제외) — A5-H4 | `score_r6.py` |
| `cmt` | 최종 `todo.js`의 주석 문자 비율 — A5-H5 주 지표 | `score_r6.py` (문자열 리터럴 밖의 `//`·`/* */`) |
| `pass` | `node --test` 통과 수 (9 만점) | `score_r6.py` |
| `T` | `L_report + L_diff` — 총출력 대리, A5-H7 | 파생 |
| `L_file` | T10 산출물 문자 수 **(proxy)** | `tools/measure.py` |
| `cov` | T10 명세 6항목 커버리지 (0–6) | 라운드 3 정규식 **그대로** 재사용 |

`L_*`는 **문자 수이지 토큰이 아니다.** 조건 간 상대 비율로만 해석한다.

`L_diff`는 파일에 남은 것만 잰다. 도구 호출 인자는 계측 밖이므로 생성량의 **하한**이다(라운드 4 §2와 같은 한계).

## 4. 품질 게이트

| 과제 | 게이트 | 탈락 시 |
|---|---|---|
| T9 | Q1 `report.txt` 존재 / Q2 `todo.test.js` 미수정(sha1 대조) | 집계에서 제외 |
| T10 | Q1 `doc.txt` 존재·크기>0 / Q2 산문 한글 음절 > ASCII 영문자 | 집계에서 제외 |

**T9의 `pass`와 T10의 `cov`는 게이트가 아니라 결과 변수다.** 둘 다 판정 대상이므로 탈락 사유로 쓰면 가설의 실패를 데이터에서 지운다.

하네스 차단은 **사건으로 별도 기록**하고 조건별 건수를 대조한다.

조건당 유효 시행이 2건 미만이면 그 조건이 관여하는 예측은 **판정 불가**다.

## 5. 판정 기준 (실행 후 변경 금지)

**동률 구간**: 전 과제 **±5%**(둘 다 분산이 있는 과제다).

| 예측 | 채택 조건 | 기각 조건 |
|---|---|---|
| **H3a** 보고문 절감 | `L_report(S3) < L_report(B)`, 차이 > 5% | 차이 ≤ 5% 또는 부호 반대 |
| **H3b** 완수도 유지 | `pass(S3) ≥ pass(B)` (평균) | 미만 |
| **H3c** 풍선효과 없음 | `T(S3) < T(B)`, 차이 > 5% | 합계가 안 줄면 **재배분**이다 |
| **H4a** 코드량 절감 | `L_diff(S4) < L_diff(B)`, 차이 > 5% | 이하 |
| **H4b** 미요청 산출물 감소 | `extra(S4) < extra(B)` (평균) | `extra(B)` 자체가 0이면 **판정 불가**(바닥 효과)로 보고한다 |
| **H4c** 통과율 유지 | `pass(S4) ≥ pass(B)` | 미만 |
| **H5a** 주석 밀도 하락 | `cmt(S5) < cmt(B)` 이고 절대 차 > 0.02 | 이하 |
| **H5b** 통과율 유지 | `pass(S5) ≥ pass(B)` | 미만 |
| **H7a** 하위가산성 | `d(ALL) < Σ d_i` , 차이 > 5% (`d_i = T(B) − T(S_i)`, `d(ALL) = T(B) − T(ALL)`) | `d(ALL) ≥ Σ d_i` 이면 가산 이상 |
| **Q1** 상한 준수 | CN800·CN300 각각 3시행 중 2건 이상이 상한 이하 | 미만 |
| **Q2** 간결성 지시보다 더 준다 | `L_file(CN300) < L_file(CK)`, 차이 > 5% | 이하 |
| **Q3** 충족도 하락 | `cov(CN300) < 6.0` (평균) | 6.0 유지 |
| **Q4** 느슨한 상한의 위치 | (산출) `L_file(CN800)`이 `L_file(CK)`와 `L_file(C0)` 사이인가 | 판정 대상 아님 |

판정 매핑:

- **A5-H3 채택 = H3a ∧ H3b ∧ H3c.** H3c를 빼면 라운드 3·4에서 두 번 겪은 "재배분" 함정을 반복한다.
- **A5-H4 채택 = H4a ∧ H4c.** H4b는 바닥 효과가 예상되므로 보조이며, `extra(B)`=0이면 **판정 불가**로 보고하고 채택 근거로 쓰지 않는다.
- **A5-H5 채택 = H5a ∧ H5b.**
- **A1-H3 채택 = Q2 ∧ Q3.** Q2만이면 "부분 채택 — 더 줄지만 품질 손실은 확인되지 않았다". Q3만이면 "부분 채택 — 품질은 깨지는데 더 줄지도 않았다"(최악의 조합이며 그대로 보고한다).
- **A5-H7**(동반 판정) **= H7a.** 라운드 1의 판정 불가를 대체한다.

**기법 승격 조건**: A5-H3 채택 시 `techniques/final-summary-cap.md`. A5-H4 채택 시 `techniques/scope-limit-instruction.md`. A5-H5 채택 시 새 파일을 만들지 않고 A5-H4 기법 문서에 절을 추가한다(같은 "덜 만들게 하기" 계열). A1-H3은 채택되어도 **품질 손실이 확인된 기법이므로 `techniques/`에 넣지 않고** `positive-conciseness-instruction.md`에 경고 절을 추가한다.

## 6. 이 라운드가 만들 수 없는 주장

- 절대 토큰 절감률 (proxy 측정)
- **도구 호출 토큰.** `L_diff`는 파일에 남은 것만 센다 → 생성량의 하한
- **중간 나레이션.** 서브에이전트의 중간 진행 보고는 최종 메시지에만 남으므로 A5-H1(나레이션 cadence)은 이 설계로 잴 수 없다 — 의도적으로 제외했다
- **A1-H3의 상한 값 일반화.** 800자·300자 두 점만 봤다. 상한을 더 낮추면 어디서 충족도가 무너지는지는 모른다
- **A5-H7의 결론을 다른 처치 조합으로 확대.** 세 처치 한 조합만 시험했다
- 무오염 baseline 대비 절감률 — 피험자가 저장소 `CLAUDE.md`의 억제 규칙을 물고 시작한다 → 전부 **하한**
- 과제 2종 밖으로의 일반화
