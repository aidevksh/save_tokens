요청 제한(rate limit) 동작 설명

## 1. 버킷 용량: 60

토큰 버킷(token bucket) 방식이다. 각 사용자는 토큰이 담긴 물통을 하나 가진다.
요청 1건에 토큰 1개가 소모되고, 물통이 비면 요청이 거절된다.
용량이 60이므로 토큰이 꽉 찬 상태에서는 한꺼번에 60건까지 통과한다(버스트 허용량).
물통은 60을 넘겨 채워지지 않는다 — 오래 쉬어도 61개가 쌓이는 일은 없다.

## 2. 리필 속도: 초당 1개

소모된 토큰은 1초에 1개씩 다시 채워진다.
따라서 장기 평균 처리 한도는 초당 1건이고, 빈 물통이 완전히 회복되는 데는 60초가 걸린다.
"초당 1건 + 순간 60건 버스트"가 이 설정의 실질적 의미다.

## 3. 집계 단위: API 키 (IP 주소가 아님)

물통은 API 키마다 하나씩 존재한다. IP 주소 기준이 아니다.

- 같은 키를 서로 다른 서버·다른 IP에서 써도 물통은 하나로 합산된다.
- 같은 IP에서 서로 다른 키를 쓰면 각각 별도 물통이므로 서로 영향이 없다.
- NAT나 공용 IP 뒤의 다른 고객이 한도를 소모하는 문제는 발생하지 않는다.

## 4. 초과 시 상태 코드: 429

토큰이 없는 상태에서 들어온 요청은 HTTP 429 (Too Many Requests)로 응답한다.
429는 요청 내용이 잘못됐다는 뜻이 아니라 지금은 때가 아니라는 뜻이므로,
같은 요청을 나중에 그대로 다시 보내면 성공한다.

## 5. 재시도 안내 헤더: Retry-After (초 단위 정수)

429 응답에는 `Retry-After` 헤더가 함께 실린다. 값은 초 단위 정수다.

    HTTP/1.1 429 Too Many Requests
    Retry-After: 3

토큰 1개가 다시 채워질 때까지 남은 시간이며, 위 예시는 3초 후 재시도하라는 뜻이다.
클라이언트는 임의 간격으로 재시도하지 말고 이 값만큼 기다린 뒤 보내야 한다.
날짜 형식(HTTP-date)은 쓰지 않는다.

## 6. 예외: admin 스코프 키

스코프가 `admin` 인 키는 제한 대상에서 제외된다. 토큰을 소모하지 않고,
429를 받지 않으며, 물통 자체가 적용되지 않는다.
운영·복구 작업이 한도에 걸려 막히지 않게 하기 위한 장치이므로
일반 트래픽에 admin 키를 쓰면 안 된다.
