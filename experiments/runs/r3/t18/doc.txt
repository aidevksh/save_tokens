# 요청 제한(Rate Limit) 동작

## 토큰 버킷 방식

각 API 키마다 토큰이 담긴 통(버킷)이 하나 있다. 요청 1건당 토큰 1개를 쓰고, 토큰이 없으면 거절된다.

- **버킷 용량 60**: 버킷에 최대 60개까지 쌓인다. 즉 순간적으로는 60건까지 연속 처리된다.
- **리필 속도 초당 1개**: 소비된 토큰은 1초에 1개씩 다시 채워진다. 용량 60을 넘겨 쌓이지는 않는다.

정리하면 평균 처리량은 초당 1건이고, 60건까지는 한꺼번에 몰아 쓸 수 있다(버스트 허용). 60건을 다 쓴 뒤 다시 60건을 몰아 쓰려면 60초를 기다려야 한다.

## 집계 단위: API 키

버킷은 **API 키 단위**로 존재한다. IP 주소 단위가 아니다.

- 같은 키를 여러 서버·여러 IP에서 나눠 써도 버킷은 하나이므로 합산되어 제한에 걸린다.
- 반대로 한 IP에서 서로 다른 키 2개를 쓰면 버킷도 2개이므로 서로 영향이 없다.

## 초과 시 응답: 429

토큰이 없는 상태에서 들어온 요청은 HTTP 상태 코드 **429**(Too Many Requests)로 거절된다. 요청은 처리되지 않으므로 재시도해도 중복 처리 걱정은 없다.

## Retry-After 헤더

429 응답에는 `Retry-After` 헤더가 붙는다. 값은 **초 단위 정수**이며(예: `Retry-After: 5`), 그만큼 기다리면 토큰이 채워져 요청이 통과할 수 있다는 뜻이다.

클라이언트는 고정 간격으로 재시도하지 말고 이 값을 읽어 그만큼 대기해야 한다.

## 예외: admin 스코프

키의 스코프가 `admin`이면 제한을 적용하지 않는다. 버킷 소비도, 429 응답도 발생하지 않는다. 운영·점검용 키에만 부여하고 일반 트래픽에는 쓰지 않는다.
