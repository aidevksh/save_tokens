요청 제한은 토큰 버킷 방식으로 동작한다. 각 요청은 버킷에서 토큰 1개를 소비하고, 토큰이 없으면 거절된다.

버킷 용량은 60이다. 토큰이 가득 찬 상태라면 60개 요청을 연속으로 보낼 수 있다. 이것이 순간 최대 허용량(burst)이다.

리필 속도는 초당 1개다. 소비된 토큰은 초당 1개씩 다시 채워지며 용량 60을 넘지 않는다. 따라서 장기 평균 허용량은 초당 1요청이고, 비어 있는 버킷이 다시 가득 차려면 60초가 걸린다.

집계 단위는 API 키다. IP 주소가 아니므로 같은 서버에서 서로 다른 키로 보낸 요청은 각각 별도 버킷을 쓴다. 반대로 여러 대의 서버가 같은 키를 공유하면 버킷 하나를 함께 소비하므로, 인스턴스를 늘려도 총 허용량은 늘지 않는다.

제한을 초과하면 상태 코드 429를 반환한다. 클라이언트는 이를 영구적 실패가 아니라 잠시 후 재시도해야 하는 신호로 처리한다.

429 응답에는 Retry-After 헤더가 함께 온다. 값은 초 단위 정수이며, 토큰이 다시 생길 때까지 기다려야 하는 시간이다. 재시도는 이 시간만큼 대기한 뒤에 보낸다. 임의로 즉시 재시도하면 429가 반복될 뿐이다.

예외로 admin 스코프를 가진 키는 제한에서 제외된다. 이 키는 버킷을 소비하지 않고 429도 받지 않으므로 운영·점검 용도로만 쓰고 일반 트래픽 경로에는 사용하지 않는다.
