요청 제한(rate limit) 동작 명세

토큰 버킷 방식으로 동작합니다. 각 요청은 버킷에서 토큰 1개를 소비하고, 토큰이 없으면 요청이 거부됩니다.

버킷 용량: 60
버킷에 최대 60개의 토큰이 담깁니다. 즉 순간적으로 최대 60개 요청을 연달아 보낼 수 있습니다(버스트 허용량).

리필 속도: 초당 1개
토큰은 초당 1개씩 다시 채워집니다. 용량 60을 넘어서는 쌓이지 않습니다. 장기 평균으로는 초당 1요청이 지속 가능한 속도입니다.

집계 단위: API 키
제한은 API 키별로 계산합니다. IP 주소 기준이 아닙니다. 따라서 여러 서버나 여러 지역에서 같은 키를 쓰면 그 요청들이 하나의 버킷을 공유하고, 반대로 같은 IP에서 서로 다른 키를 쓰면 각각 별도의 버킷을 가집니다.

초과 시 상태 코드: 429
토큰이 없는 상태에서 들어온 요청은 HTTP 429(Too Many Requests)로 응답합니다.

재시도 안내 헤더: Retry-After
429 응답에는 Retry-After 헤더가 함께 옵니다. 값은 초 단위 정수이며, 그 시간만큼 기다린 뒤 재시도하면 됩니다. 클라이언트는 이 값을 읽어서 대기하도록 구현하세요.

예외: admin 스코프 키
admin 스코프를 가진 키는 제한을 적용받지 않습니다. 토큰 소비나 429 없이 통과합니다.
