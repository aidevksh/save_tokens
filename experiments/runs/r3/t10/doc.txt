요청 제한(rate limit) 동작 명세

이 서비스의 요청 제한은 토큰 버킷(token bucket) 방식으로 동작한다. 요청 하나가 버킷에서 토큰 하나를 소모하고, 토큰이 없으면 요청이 거절된다.

1. 버킷 용량: 60
버킷에 담을 수 있는 토큰의 최대 개수가 60이다. 즉 한동안 요청이 없었다면 순간적으로 최대 60건까지 연속 처리된다. 이 값이 순간 최대 처리량(burst)의 상한이다.

2. 리필 속도: 초당 1개
소모된 토큰은 초당 1개씩 다시 채워진다. 따라서 장기 평균 허용량은 초당 1요청이다. 채워지는 양은 용량 60을 넘지 않는다.

3. 집계 단위: API 키
버킷은 API 키마다 하나씩 따로 존재한다. IP 주소 기준이 아니므로, 같은 서버에서 서로 다른 키로 보낸 요청은 서로의 한도를 깎지 않고, 반대로 여러 서버에서 같은 키를 공유하면 한 버킷을 함께 나눠 쓴다. 클라이언트를 늘려 한도를 늘릴 수는 없다.

4. 초과 시 상태 코드: 429
토큰이 없는 상태에서 들어온 요청은 처리되지 않고 HTTP 429(Too Many Requests)로 응답한다. 요청 자체가 잘못된 것이 아니므로 요청 내용을 바꿀 필요는 없고, 기다린 뒤 다시 보내면 된다.

5. 재시도 안내 헤더: Retry-After
429 응답에는 Retry-After 헤더가 함께 온다. 값은 초 단위 정수이며, 그 시간만큼 기다린 뒤 재시도하라는 뜻이다. 클라이언트는 임의 간격으로 재시도하지 말고 이 값을 읽어 대기해야 한다.

6. 예외: admin 스코프 키
admin 스코프를 가진 키는 요청 제한을 적용받지 않는다. 토큰을 소모하지 않으며 429도 받지 않는다. 일반 서비스 트래픽에 admin 키를 쓰면 제한이 사실상 사라져 장애 시 보호막이 없어지므로, 운영·관리 용도로만 사용한다.
