요청 제한(Rate Limit) 동작 설명

방식: 토큰 버킷. 요청 1건이 토큰 1개를 소모하고, 토큰이 없으면 거절된다.

1) 버킷 용량 = 60
   버킷에 최대 60개까지 토큰이 쌓인다. 즉 한동안 요청이 없었다면 순간적으로 60건까지 연속 처리된다(버스트 허용량).

2) 리필 속도 = 초당 1개
   토큰이 1초에 1개씩 다시 채워진다. 따라서 지속 가능한 평균 속도는 초당 1건이고, 빈 버킷이 다 차기까지는 60초가 걸린다.

3) 집계 단위 = API 키
   버킷은 API 키마다 하나씩 존재한다. IP 주소 기준이 아니므로, 같은 IP에서 서로 다른 키로 호출하면 한도를 따로 쓰고, 반대로 여러 서버·여러 IP에서 같은 키를 쓰면 하나의 한도를 나눠 쓴다.

4) 초과 시 상태 코드 = 429
   토큰이 없는 상태에서 들어온 요청은 처리되지 않고 HTTP 429(Too Many Requests)로 응답한다.

5) 재시도 안내 헤더 = Retry-After
   429 응답에는 Retry-After 헤더가 붙고, 값은 초 단위 정수다. 예: `Retry-After: 5` → 5초 후 재시도. 클라이언트는 이 값만큼 기다린 뒤 재시도하도록 구현한다(즉시 재시도 반복은 계속 429만 받는다).

6) 예외 = admin 스코프 키
   admin 스코프를 가진 키는 제한 대상에서 제외되어 버킷 검사를 거치지 않는다. 일반 스코프 키에만 위 규칙이 적용된다.
