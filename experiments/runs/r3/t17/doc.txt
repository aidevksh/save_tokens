요청 제한(Rate Limit) 동작 명세 — 신입 개발자용 설명서

이 문서는 우리 서비스가 들어오는 요청을 어떤 규칙으로 제한하는지 설명합니다.
방식은 토큰 버킷(token bucket)입니다. 요청을 보낼 때마다 버킷에서 토큰 1개를 꺼내 쓰고,
버킷이 비면 더 이상 요청을 받지 않습니다. 토큰은 시간이 지나면서 다시 채워집니다.


1) 버킷 용량: 60

버킷에 한 번에 담아 둘 수 있는 토큰의 최대 개수가 60개입니다.
즉 한동안 요청을 보내지 않아 버킷이 꽉 찬 상태라면, 순간적으로 최대 60개의 요청을
연속해서 보낼 수 있습니다. 이것을 버스트(burst) 허용량이라고 부릅니다.
토큰이 60개를 넘어서 쌓이는 일은 없습니다. 꽉 찬 뒤에 채워지는 토큰은 그냥 버려집니다.


2) 리필 속도: 초당 1개

빈 자리는 1초에 1개씩 다시 채워집니다.
그래서 장기적으로 유지할 수 있는 평균 속도는 초당 1요청입니다.
버킷을 60개까지 완전히 비운 뒤 다시 꽉 채우려면 60초가 걸립니다.

예시:
- 60개를 한 번에 몰아 쓰면 버킷이 0이 되고, 그 직후 요청은 거절됩니다.
- 1초 기다리면 토큰이 1개 생기므로 요청 1개를 보낼 수 있습니다.
- 초당 1개 이하로만 꾸준히 보내면 사실상 제한에 걸리지 않습니다.

정리하면 용량 60은 "순간에 몰아 쓸 수 있는 양", 리필 초당 1개는 "꾸준히 쓸 수 있는 속도"입니다.


3) 집계 단위: API 키 (IP 주소가 아님)

버킷은 API 키마다 하나씩 따로 존재합니다. IP 주소 기준이 아닙니다.
이 점이 실무에서 중요한 이유는 다음과 같습니다.

- 같은 IP(같은 사무실, 같은 NAT, 같은 서버)에서 서로 다른 API 키로 요청을 보내면
  각 키가 자기 버킷을 쓰므로 서로 영향을 주지 않습니다.
- 반대로 하나의 API 키를 여러 서버나 여러 인스턴스가 공유하면
  그 모두가 같은 버킷 하나를 나눠 쓰게 됩니다. 인스턴스를 늘려도 한도는 늘어나지 않습니다.
- IP를 바꾸는 것으로는 제한을 피할 수 없습니다.


4) 초과 시 상태 코드: 429

버킷에 토큰이 없는 상태에서 요청이 들어오면 HTTP 상태 코드 429를 반환합니다.
429는 Too Many Requests(요청이 너무 많음)를 뜻합니다.

클라이언트를 만들 때는 429를 400번대 일반 오류나 서버 장애(5xx)와 다르게 다뤄야 합니다.
429는 "요청 내용이 잘못됐다"는 뜻이 아니라 "지금은 너무 빠르다, 잠시 뒤에 다시 보내라"는 뜻입니다.
따라서 요청 내용을 고치는 게 아니라, 기다린 뒤 같은 요청을 그대로 재시도하는 것이 맞습니다.


5) 재시도 안내 헤더: Retry-After (초 단위 정수)

429 응답에는 Retry-After 헤더가 함께 들어갑니다.
값은 초 단위 정수입니다. 날짜 형식이 아니라 그냥 숫자이며, "몇 초 뒤에 다시 시도하면 되는지"를 뜻합니다.

예: Retry-After: 5  →  5초 뒤에 재시도하십시오.

클라이언트 구현 지침:
- 재시도 간격을 임의로 정하지 말고 Retry-After 값을 그대로 사용하십시오.
- 429를 받고 즉시 다시 보내면 또 429를 받게 되고, 서버 부하만 늘어납니다.
- 429를 받았을 때 로그에 Retry-After 값을 남겨 두면 나중에 원인 분석이 쉬워집니다.


6) 예외: admin 스코프 키는 제한에서 제외

API 키가 admin 스코프를 가진 경우에는 요청 제한을 적용하지 않습니다.
이 키로 보내는 요청은 버킷을 소모하지 않으며 429도 받지 않습니다.

주의할 점:
- 운영·관리 목적의 키이므로 일반 애플리케이션 트래픽에 쓰지 마십시오.
  제한이 없다는 것은 실수로 폭주하는 코드를 서버가 막아 주지 못한다는 뜻이기도 합니다.
- 로컬에서 admin 키로 테스트하면 제한 동작을 전혀 보지 못합니다.
  429 처리나 Retry-After 처리 코드를 검증할 때는 반드시 일반 스코프 키로 시험하십시오.


요약 표

  항목                | 값
  --------------------|------------------------------------------
  버킷 용량           | 60 (최대 버스트 60요청)
  리필 속도           | 초당 1개 (평균 초당 1요청)
  집계 단위           | API 키 단위 (IP 주소 아님)
  초과 시 상태 코드   | 429
  재시도 안내 헤더    | Retry-After (초 단위 정수)
  예외                | admin 스코프 키는 제한 제외
