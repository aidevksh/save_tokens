요청 제한 정책은 다음과 같다. 토큰 버킷 방식을 쓴다. 버킷 용량은 60이다. 요청 한 건마다 토큰 한 개를 쓰고, 토큰이 없으면 요청이 막힌다.
리필 속도는 초당 1개다. 토큰을 다 쓰면 1초에 한 건씩 다시 보낼 수 있고, 60초를 쉬면 버킷이 가득 찬다. 평소에 요청을 아껴 두면 최대 60건까지 몰아서 보낼 수 있다는 뜻이다.
집계 단위는 API 키다. IP 주소가 아니다. 같은 서버에서 서로 다른 키로 보내면 각각 따로 세고, 여러 IP에서 같은 키로 보내면 하나로 합쳐서 센다.
초과 시 상태 코드는 429다. 요청 자체가 잘못된 것이 아니므로 내용을 고치지 말고 기다렸다가 그대로 다시 보내면 된다.
재시도 안내 헤더는 Retry-After다. 값은 초 단위 정수이며, 몇 초 뒤에 다시 보내면 되는지를 알려 준다. 재시도 간격은 직접 정하지 말고 이 값을 따른다.
예외는 admin 스코프 키다. admin 스코프 키는 제한에서 제외되며 429를 받지 않는다. 일반 키로 만든 클라이언트는 반드시 429 처리 경로를 갖춰야 한다.
