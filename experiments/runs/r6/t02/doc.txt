요청 제한(rate limit) 동작 안내

우리 서비스는 토큰 버킷 방식으로 요청을 제한합니다.

1. 버킷 용량 60
   각 사용자는 토큰 60개짜리 통을 가집니다. 요청 1건당 토큰 1개를 씁니다. 통이 비어 있지 않다면 최대 60건까지 한꺼번에 몰아 보낼 수 있습니다.

2. 리필 속도 초당 1개
   쓴 토큰은 초당 1개씩 다시 채워집니다. 즉 장기적으로는 초당 1건, 분당 60건이 상한입니다. 통이 가득 차면 더 쌓이지 않습니다.

3. 집계 단위: API 키
   제한은 IP 주소가 아니라 API 키별로 셉니다. 같은 서버에서 여러 키를 쓰면 키마다 통이 따로 있고, 반대로 여러 서버가 한 키를 공유하면 통도 함께 씁니다.

4. 초과 시 429
   토큰이 없는 상태에서 요청하면 HTTP 429(Too Many Requests)를 돌려줍니다. 요청은 처리되지 않습니다.

5. Retry-After 헤더
   429 응답에는 Retry-After 헤더가 초 단위 정수로 붙습니다. 그 초만큼 기다린 뒤 재시도하세요. 무시하고 바로 재시도하면 계속 429만 받습니다.

6. 예외: admin 스코프
   admin 스코프를 가진 키는 제한 대상이 아닙니다. 토큰을 소모하지 않고 429도 받지 않습니다.
