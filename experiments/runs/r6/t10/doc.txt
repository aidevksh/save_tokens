요청 제한(Rate Limit) 동작 안내

우리 서비스는 토큰 버킷 방식으로 요청량을 제한합니다.

1) 버킷 용량 60
   각 사용 주체는 최대 60개의 토큰을 쌓아둘 수 있습니다. 요청 1건마다 토큰 1개를 씁니다. 따라서 한가하다가 갑자기 몰아 보내도 연속 60건까지는 통과합니다.

2) 리필 속도 초당 1개
   쓴 토큰은 1초에 1개씩 다시 채워집니다. 즉 평균적으로는 초당 1건, 최대 몰아치기는 60건입니다. 빈 버킷이 가득 차려면 60초가 걸립니다.

3) 집계 단위: API 키
   버킷은 API 키마다 하나씩 있습니다. IP 주소 기준이 아니므로, 같은 서버에서 여러 키를 쓰면 각각 별도로 계산되고, 반대로 여러 IP에서 같은 키를 쓰면 합산됩니다.

4) 초과 시 429
   토큰이 없는 상태에서 요청하면 HTTP 429(Too Many Requests)로 거절합니다.

5) Retry-After 헤더
   429 응답에는 Retry-After 헤더가 초 단위 정수로 붙습니다. 그 초만큼 기다린 뒤 재시도하세요. 임의 간격으로 즉시 재시도하면 계속 429를 받습니다.

6) 예외: admin 스코프
   admin 스코프를 가진 키는 제한 대상에서 제외되어 429가 발생하지 않습니다. 운영용이므로 일반 기능에 사용하지 마세요.
