웹훅 전달 명세

용어
- 이벤트: 주문 도메인에서 발생한 사실 1건.
- 전달: 그 이벤트를 엔드포인트 1개에 보내는 시도 1건. 이벤트 1건이 엔드포인트 3개에 나가면 전달은 3건.
- 실패·재시도는 전달 단위로 센다.

구조
주문 상태가 변하면 이벤트 버스에 이벤트가 올라가고, 전달기가 구독 중인 엔드포인트마다 HTTP POST로 보낸다. 엔드포인트는 팀별로 등록하며 한 팀이 여러 개를 둘 수 있다. 엔드포인트마다 큐가 독립이라 한 곳이 느려도 다른 곳은 밀리지 않는다.

규약 10가지
1. 재시도 횟수 — 2xx가 아니면 최대 5회 재시도. 5회 모두 실패하면 폐기하고 전달 로그에 dropped로 남는다.
2. 백오프 — 지수 백오프. 첫 간격 2초, 실패마다 2배, 상한 64초. jitter 없음.
3. 서명 헤더 — 모든 요청에 X-Signature. 본문 전체를 엔드포인트 비밀키로 HMAC-SHA256 한 16진수 문자열. 본문 파싱 전에 먼저 검증할 것.
4. 타임아웃 — 응답 헤더가 10초 안에 오지 않으면 실패. 연결/읽기를 나누지 않고 전체 10초.
5. 중복 전달 — at-least-once. 같은 이벤트가 두 번 이상 올 수 있으므로 event_id로 멱등 처리할 것.
6. 순서 보장 — 없음. 나중 이벤트가 먼저 올 수 있으므로 occurred_at으로 정렬할 것.
7. 페이로드 크기 상한 — 256KB. 넘으면 본문 대신 payload_url이 들어가고 수신 측이 직접 내려받는다.
8. 이벤트 타입 — order.created, order.updated, order.canceled 세 가지. 구독하지 않은 타입은 오지 않는다.
9. 자동 비활성화 — 한 엔드포인트에서 연속 실패 100회 또는 실패 상태 7일이면 자동 비활성화하고 관리자에게 메일을 보낸다.
10. 재전송 API — POST /webhooks/{id}/redeliver. 최근 30일치 대상, 호출 1회당 최대 100건.

전달 로그 (관리 콘솔 전달 탭)
- delivery_id: 전달 시도 1건의 식별자
- event_id: 원본 이벤트 식별자. 재시도해도 동일
- attempt: 몇 번째 시도인지, 1부터
- status_code: 수신 서버가 준 HTTP 상태 코드. 타임아웃이면 빈 값
- duration_ms: 요청 후 응답 헤더까지 걸린 밀리초
- result: ok / retrying / dropped

본문 예시
{
  "event_id": "evt_01H9Z2",
  "type": "order.created",
  "occurred_at": "2026-03-14T05:21:09Z",
  "data": {"order_id": "ord_8812", "amount": 42900, "currency": "KRW"}
}

비밀키
등록 시 한 번만 보여주고 이후 조회 불가. 분실하면 콘솔에서 회전한다. 회전 직후 5분간은 옛 키와 새 키 서명을 모두 받는다. 회전 이력은 전달 탭에서 확인한다.
