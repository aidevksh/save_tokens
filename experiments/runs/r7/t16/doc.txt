요청 제한(Rate Limit) 안내

토큰 버킷 방식입니다.

1. 버킷 용량 60
   요청 1건에 토큰 1개를 씁니다. 가득 찬 상태에서 한 번에 최대 60건까지 몰아 보낼 수 있습니다.

2. 리필 속도 초당 1개
   토큰이 초당 1개씩 다시 채워집니다. 즉 평균 처리량은 초당 1건이고, 60까지는 순간적으로 몰아 쓸 수 있습니다.

3. 집계 단위: API 키
   IP 주소가 아니라 API 키마다 버킷이 따로 있습니다. 같은 서버에서 여러 키를 쓰면 각각 별도 한도이고, 여러 서버가 한 키를 공유하면 한도를 나눠 씁니다.

4. 초과 시 429
   토큰이 없으면 요청이 처리되지 않고 HTTP 429(Too Many Requests)를 돌려줍니다.

5. Retry-After 헤더
   429 응답에는 Retry-After 헤더가 붙습니다. 값은 초 단위 정수이며, 그만큼 기다린 뒤 재시도하면 됩니다. 이 값을 무시하고 즉시 재시도하지 마세요.

6. 예외: admin 스코프
   admin 스코프 키는 제한을 적용받지 않습니다. 버킷을 소모하지 않고 429도 발생하지 않습니다.
