웹훅 수신 가이드

주문 도메인에서 상태 변화가 생기면 이벤트가 이벤트 버스에 올라가고, 전달기가 구독 중인
엔드포인트마다 HTTP POST 로 보냅니다. 엔드포인트는 팀별로 등록하고 한 팀이 여러 개를 둘 수
있으며, 엔드포인트마다 큐가 독립이라 한쪽이 느려도 다른 쪽은 밀리지 않습니다.

용어: '이벤트'는 발생한 사실 하나, '전달'은 이벤트를 엔드포인트 하나에 보내는 시도 하나입니다.
이벤트 1건이 엔드포인트 3개에 나가면 전달은 3건이고, 실패와 재시도는 전달 단위로 셉니다.

규약 10가지

1. 재시도 횟수 — 2xx 가 아니면 최대 5회 재시도하고, 5회 모두 실패하면 폐기하고 전달 로그에
   `dropped` 로 남깁니다.
2. 백오프 — 지수 백오프. 첫 간격 2초에서 실패할 때마다 2배, 상한 64초. jitter 없음.
3. 서명 헤더 — 모든 요청에 `X-Signature`. 본문 전체를 엔드포인트 비밀키로 HMAC-SHA256 한
   16진수 문자열이며, 본문을 파싱하기 전에 먼저 검증해야 합니다.
4. 타임아웃 — 10초 안에 응답 헤더가 오지 않으면 실패. 연결/읽기를 나누지 않고 전체 10초입니다.
5. 중복 전달 — at-least-once 이므로 같은 이벤트가 두 번 이상 올 수 있습니다. 본문 `event_id`
   로 멱등 처리하세요.
6. 순서 보장 — 순서를 보장하지 않습니다. 본문 `occurred_at` 으로 정렬하세요.
7. 페이로드 크기 상한 — 본문은 256KB 이하. 초과 시 본문 대신 `payload_url` 이 들어가고
   수신 측이 그 주소에서 내려받습니다.
8. 이벤트 타입 — `order.created`, `order.updated`, `order.canceled` 세 가지. 구독하지 않은
   타입은 전달되지 않습니다.
9. 자동 비활성화 — 한 엔드포인트에서 연속 실패 100회 또는 실패 상태 7일이면 자동 비활성화하고
   관리자에게 메일을 보냅니다.
10. 재전송 API — `POST /webhooks/{id}/redeliver`. 최근 30일치가 대상이고 호출당 최대 100건입니다.

본문 예시

{
  "event_id": "evt_01H9Z2",
  "type": "order.created",
  "occurred_at": "2026-03-14T05:21:09Z",
  "data": {"order_id": "ord_8812", "amount": 42900, "currency": "KRW"}
}

전달 로그 (관리 콘솔 전달 탭)

delivery_id  전달 시도 하나의 식별자
event_id     원본 이벤트 식별자. 재시도해도 값이 같음
attempt      몇 번째 시도인지. 1 부터
status_code  수신 서버가 준 HTTP 상태 코드. 타임아웃이면 빈 값
duration_ms  요청부터 응답 헤더 수신까지의 밀리초
result       ok / retrying / dropped

비밀키

등록할 때 한 번만 표시하고 이후에는 볼 수 없습니다. 분실하면 콘솔에서 회전(rotate)하며, 회전
직후 5분 동안은 옛 키와 새 키로 만든 서명을 모두 받습니다. 회전 이력도 전달 탭에서 봅니다.
