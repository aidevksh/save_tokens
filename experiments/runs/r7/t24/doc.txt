요청 제한(Rate Limit) 동작 안내

토큰 버킷 방식입니다.

1. 버킷 용량 60
   각 키는 토큰 60개를 담는 버킷을 가집니다. 요청 1건에 토큰 1개를 씁니다.
   따라서 순간적으로 최대 60건까지 몰아서 보낼 수 있습니다(버스트).

2. 리필 속도 초당 1개
   토큰은 1초에 1개씩 다시 채워지며, 60을 넘겨 쌓이지 않습니다.
   즉 장기 평균 허용량은 초당 1건입니다.

3. 집계 단위: API 키
   제한은 API 키별로 계산합니다. IP 주소 기준이 아닙니다.
   같은 키를 여러 서버에서 나눠 쓰면 그 합계가 하나의 버킷을 소모합니다.
   반대로 IP가 같아도 키가 다르면 서로 영향을 주지 않습니다.

4. 초과 시 상태 코드 429
   버킷이 비었을 때 들어온 요청은 처리되지 않고 HTTP 429(Too Many Requests)를 반환합니다.

5. Retry-After 헤더
   429 응답에는 `Retry-After` 헤더가 붙습니다. 값은 초 단위 정수입니다.
   예: `Retry-After: 3` → 3초 뒤에 재시도하십시오.
   클라이언트는 이 값을 읽어 대기한 뒤 재시도하도록 구현합니다. 즉시 재시도는 429만 늘립니다.

6. 예외: admin 스코프
   `admin` 스코프를 가진 키는 제한을 적용받지 않습니다. 버킷 소모도, 429도 없습니다.
   운영·배치 작업용이므로 일반 서비스 트래픽에 쓰지 않습니다.
