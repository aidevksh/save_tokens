웹훅 수신 개발 가이드

주문 도메인에서 상태 변화가 생기면 이벤트가 이벤트 버스에 올라가고, 전달기가 구독 중인 엔드포인트마다 HTTP POST 를 보냅니다. 엔드포인트는 팀별로 여러 개 등록할 수 있고 각각 독립된 큐를 쓰므로 한 엔드포인트가 느려도 다른 쪽은 밀리지 않습니다.

용어: '이벤트'는 도메인에서 발생한 사실 하나, '전달'은 그 이벤트를 엔드포인트 하나에 보내는 시도 하나입니다. 이벤트 1건이 엔드포인트 3개에 나가면 전달은 3건이고, 실패와 재시도는 전달 단위로 셉니다.

1. 재시도 횟수
2xx 가 아니면 최대 5회까지 다시 보냅니다. 5회 모두 실패하면 폐기되고 전달 로그에 `dropped` 로 남습니다.

2. 백오프
지수 백오프입니다. 첫 간격 2초, 실패할 때마다 2배, 상한 64초. 무작위 흔들림(jitter)은 없습니다.

3. 서명 헤더
모든 요청에 `X-Signature` 가 붙습니다. 값은 요청 본문 전체를 엔드포인트 비밀키로 HMAC-SHA256 한 결과의 16진수 문자열입니다. 본문을 파싱하기 전에 이 값을 먼저 검증하세요.

4. 타임아웃
10초 안에 응답 헤더를 보내지 않으면 실패입니다. 연결/읽기를 나누지 않고 전체 10초로 잽니다.

5. 중복 전달
전달 보장은 at-least-once 입니다. 같은 이벤트가 두 번 이상 올 수 있으니 본문의 `event_id` 로 멱등 처리를 하세요.

6. 순서 보장
순서는 보장되지 않습니다. 나중에 발생한 이벤트가 먼저 올 수 있으니 본문의 `occurred_at` 으로 정렬하세요.

7. 페이로드 크기 상한
본문은 256KB 를 넘지 않습니다. 넘으면 본문 대신 `payload_url` 이 들어가고 수신 측이 그 주소에서 직접 내려받아야 합니다.

8. 이벤트 타입
`order.created`, `order.updated`, `order.canceled` 세 가지입니다. 구독하지 않은 타입은 전달되지 않습니다.

9. 자동 비활성화
한 엔드포인트에서 연속 실패가 100회에 이르거나 실패 상태가 7일 이어지면 자동 비활성화되고 관리자에게 메일이 갑니다.

10. 재전송 API
`POST /webhooks/{id}/redeliver` 로 지난 이벤트를 다시 보냅니다. 대상은 최근 30일치, 한 번에 최대 100건입니다.

전달 로그 (관리 콘솔 전달 탭)

| 필드 | 뜻 |
|---|---|
| `delivery_id` | 전달 시도 하나의 식별자 |
| `event_id` | 원본 이벤트 식별자. 재시도해도 값이 같습니다 |
| `attempt` | 몇 번째 시도인지. 1 부터 |
| `status_code` | 수신 서버가 준 HTTP 상태 코드. 타임아웃이면 비어 있음 |
| `duration_ms` | 요청 발송부터 응답 헤더 수신까지 밀리초 |
| `result` | `ok` / `retrying` / `dropped` |

본문 예시

```json
{
  "event_id": "evt_01H9Z2",
  "type": "order.created",
  "occurred_at": "2026-03-14T05:21:09Z",
  "data": {"order_id": "ord_8812", "amount": 42900, "currency": "KRW"}
}
```

비밀키는 엔드포인트 등록 시 한 번만 보여주고 이후 다시 볼 수 없습니다. 분실하면 콘솔에서 회전(rotate)하며, 회전 직후 5분 동안은 옛 키와 새 키 서명을 둘 다 받아 줍니다. 회전 이력도 전달 탭에서 확인할 수 있습니다.
