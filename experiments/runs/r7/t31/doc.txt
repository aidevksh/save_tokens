웹훅 전달 규약 (신입 백엔드 개발자용)

주문 도메인의 상태 변화는 이벤트 버스에 이벤트 1건으로 올라가고, 전달기가 그 타입을 구독한
엔드포인트마다 HTTP POST 를 하나씩 보낸다. 엔드포인트는 팀별로 등록하며 한 팀이 여러 개를
가질 수 있고, 엔드포인트마다 큐가 독립이라 한 곳이 느려도 다른 곳은 밀리지 않는다.

용어
- 이벤트: 도메인에서 발생한 사실 1건.
- 전달: 그 이벤트를 엔드포인트 1개로 보내는 시도 1건. 이벤트 1건 × 엔드포인트 3개 = 전달 3건.
- 실패와 재시도는 전달 단위로 센다.

수신 측이 지켜야 할 10가지

1. 재시도 횟수 — 2xx 가 아니면 최대 5회 재시도. 5회 모두 실패하면 폐기되고 전달 로그에
   result=dropped 로 남는다.
2. 백오프 — 지수 백오프. 첫 간격 2초, 실패마다 2배, 상한 64초(2→4→8→…→64). jitter 없음.
3. 서명 헤더 — 모든 요청에 X-Signature. 값은 요청 본문 전체를 엔드포인트 비밀키로
   HMAC-SHA256 한 결과의 16진수 문자열. 본문을 파싱하기 전에 먼저 검증한다.
4. 타임아웃 — 10초 안에 응답 헤더가 오지 않으면 실패. 연결/읽기를 나누지 않고 전체 10초.
5. 중복 전달 — at-least-once 보장이라 같은 이벤트가 두 번 이상 올 수 있다. 본문의 event_id
   로 멱등 처리한다.
6. 순서 보장 — 순서를 보장하지 않는다. 나중 이벤트가 먼저 올 수 있으므로 occurred_at 으로
   정렬한다.
7. 페이로드 크기 상한 — 본문 256KB 이하. 초과하면 본문 대신 payload_url 이 들어오고 수신
   측이 그 주소에서 내려받는다.
8. 이벤트 타입 — order.created, order.updated, order.canceled 세 가지. 구독하지 않은 타입은
   오지 않는다.
9. 자동 비활성화 — 한 엔드포인트에서 연속 실패 100회 또는 실패 상태 7일 지속이면 자동
   비활성화하고 관리자에게 메일을 보낸다.
10. 재전송 API — POST /webhooks/{id}/redeliver 로 지난 이벤트를 다시 보낸다. 최근 30일치가
    대상이고 호출 1회당 최대 100건.

본문 예시

{
  "event_id": "evt_01H9Z2",
  "type": "order.created",
  "occurred_at": "2026-03-14T05:21:09Z",
  "data": {"order_id": "ord_8812", "amount": 42900, "currency": "KRW"}
}

전달 로그 (관리 콘솔 > 전달 탭)

delivery_id   전달 시도 1건의 식별자
event_id      원본 이벤트 식별자. 재시도해도 값이 같다
attempt       몇 번째 시도인지. 1부터
status_code   수신 서버가 준 HTTP 상태 코드. 타임아웃이면 빈 값
duration_ms   요청 전송부터 응답 헤더 수신까지 걸린 밀리초
result        ok / retrying / dropped

비밀키

등록 시 한 번만 보여주고 이후에는 다시 볼 수 없다. 분실하면 콘솔에서 회전(rotate)하며,
회전 직후 5분 동안은 옛 키와 새 키로 만든 서명을 둘 다 받아 준다. 회전 이력도 전달 탭에서
확인할 수 있다.
