웹훅 전달 명세 (수신 측 개발자용)

주문 도메인에서 상태 변화가 생기면 이벤트 버스에 이벤트가 올라가고, 전달기가 그 이벤트를 구독 중인 엔드포인트마다 HTTP POST 로 보냅니다. 엔드포인트는 팀별로 등록하고 한 팀이 여러 개를 둘 수 있으며, 엔드포인트마다 큐가 독립이라 한 곳이 느려도 다른 곳은 밀리지 않습니다.

용어
- 이벤트: 도메인에서 발생한 사실 하나.
- 전달: 이벤트 하나를 엔드포인트 하나에 보내는 시도 하나. 이벤트 1건이 엔드포인트 3개에 나가면 전달은 3건이고, 실패·재시도는 전달 단위로 셉니다.

규약 10가지

1. 재시도 횟수 — 2xx 가 아니면 최대 5회 재시도합니다. 5회 모두 실패하면 폐기되고 전달 로그에 `dropped` 으로 남습니다.

2. 백오프 — 지수 백오프. 첫 간격 2초, 실패할 때마다 2배, 상한 64초. 무작위 흔들림(jitter)은 없습니다.

3. 서명 헤더 — 모든 요청에 `X-Signature` 가 붙습니다. 값은 본문 전체를 엔드포인트 비밀키로 HMAC-SHA256 한 16진수 문자열이며, 본문을 파싱하기 전에 먼저 검증해야 합니다.

4. 타임아웃 — 10초 안에 응답 헤더가 오지 않으면 실패입니다. 연결/읽기를 나누지 않고 전체 10초로 잽니다.

5. 중복 전달 — 보장 수준은 at-least-once. 같은 이벤트가 두 번 이상 올 수 있으니 본문의 `event_id` 로 멱등 처리하세요.

6. 순서 보장 — 순서는 보장하지 않습니다. 나중 이벤트가 먼저 올 수 있으니 `occurred_at` 으로 정렬하세요.

7. 페이로드 크기 상한 — 본문은 256KB 이하입니다. 넘으면 본문 대신 `payload_url` 이 들어가고 수신 측이 직접 내려받습니다.

8. 이벤트 타입 — `order.created`, `order.updated`, `order.canceled` 세 가지. 구독하지 않은 타입은 오지 않습니다.

9. 자동 비활성화 — 한 엔드포인트에서 연속 실패 100회 또는 실패 상태 7일이면 자동 비활성화하고 관리자에게 메일을 보냅니다.

10. 재전송 API — `POST /webhooks/{id}/redeliver` 로 지난 이벤트를 다시 받습니다. 최근 30일치, 호출당 최대 100건.

본문 예시
{
  "event_id": "evt_01H9Z2",
  "type": "order.created",
  "occurred_at": "2026-03-14T05:21:09Z",
  "data": {"order_id": "ord_8812", "amount": 42900, "currency": "KRW"}
}

전달 로그 (관리 콘솔 전달 탭)
- `delivery_id`: 전달 시도 식별자
- `event_id`: 원본 이벤트 식별자, 재시도해도 동일
- `attempt`: 몇 번째 시도인지, 1부터
- `status_code`: 수신 서버가 준 HTTP 상태 코드, 타임아웃이면 빈 값
- `duration_ms`: 요청부터 응답 헤더까지 밀리초
- `result`: `ok` / `retrying` / `dropped`

비밀키
등록할 때 한 번만 보여주고 이후에는 볼 수 없습니다. 분실하면 콘솔에서 회전(rotate)하고, 회전 후 5분간은 옛 키와 새 키 서명을 모두 받아 줍니다. 회전 이력도 전달 탭에서 확인합니다.
