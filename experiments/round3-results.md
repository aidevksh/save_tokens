## 2. A2-H6 — 마크다운 표 비용 · **채택**

| 형식 | 문자 수 | JSON 대비 | TSV 대비 | 셀 정확도 |
|---|---|---|---|---|
| 전체 키 JSON (라운드 1) | 2,093 | — | +181.3% | 1.0 |
| **마크다운 표** | **1,028** | **−50.9%** | **+38.2%** | 1.0 |
| 헤더 TSV | 744 | −64.5% | — | 1.0 |

세 형식이 **정확히 같은 96셀**을 담았고 정확도가 모두 1.0이다. 순서는 `TSV < 마크다운 표 < JSON`.

### 오버헤드가 어디서 오는지 (항등식)

TSV 행의 구분자는 탭 7개(7자). 마크다운 행은 `| ` + `" | "`×7 + ` |` = 25자. **행당 차이 18자.**

```
L_MD − L_TSV = 18 × (레코드 수 + 1) + 50
             = 18 × 13 + 50 = 284자
실측          = 1,028 − 744 = 284자     (오차 0)
```

`+1`은 헤더 행, `50`은 구분 행(`| --- | … |` 49자 + 개행)이다. **레코드당 18자는 고정비이므로 오버헤드는 레코드 수에 선형으로 커진다.** 이는 A2-H1에서 확정한 "JSON 절감의 79.6%가 반복된 키 이름"과 같은 구조 — 반복 단위가 키 이름에서 파이프·공백으로 바뀐 것뿐이다.

역으로 **셀이 길어지면 상대 오버헤드는 줄어든다.** 이 과제의 셀은 평균 8.5자로 짧아 18자가 크게 보인다. 셀당 50자짜리 표라면 같은 18자가 −38.2%가 아니라 −8% 수준이 된다.

### 복제 확인 (P8)

T 조건 산출물 744자는 라운드 1 H1-B와 **문자 수 완전 일치(+0.0%)**. 두 시행 모두 바이트 동일(분산 0). M 조건도 두 시행 바이트 동일. 결정적 과제의 분산 0이 이 파라미터 수준에서 재확인됐다.

**기법 반영**: 새 파일을 만들지 않고 [`techniques/tabular-payload-tsv-over-json.md`](../techniques/tabular-payload-tsv-over-json.md)에 경계 절을 추가했다. 같은 기법의 적용 경계이지 별도 기법이 아니다.

## 3. A1-H1 — 긍정형 vs 부정형 · **채택**

| 비교 | 결과 | 사전등록 기준 |
|---|---|---|
| P2a 무처치 → 부정형 | **−62.3%** | 충족 (>5%) |
| P2b 무처치 → 긍정형 | **−69.3%** | 충족 (>5%) |
| P3 부정형 → 긍정형 | **−18.7%** | 충족 (>5%) |

48자짜리 지시문 한 줄이 산출물을 **2,425자 → 744자**로 줄였고 커버리지는 6/6을 유지했다. 처치 문단 길이는 두 조건 모두 정확히 48자다(생성기 검증) — 절감이 프롬프트 길이 차이에서 온 것이 아니다.

### 이 채택에 붙는 세 가지 유보

**(1) 분포가 겹친다.** 긍정형 3시행(656 / 899 / **676**)과 부정형 3시행(**723** / 1144 / 876)에서 긍정형 t10(899)이 부정형 두 시행보다 길다. 평균은 −18.7%로 벌어지지만 순위 분리는 완성되지 않았다. n=3에서 P3의 **부호는 신뢰하되 크기는 신뢰하지 않는다.**

**(2) 언어 구성 격차가 P3를 부풀릴 수 있다.** `hangul_ratio`가 부정형 0.828, 긍정형 0.882다. 부정형 산출물에 영문이 더 많고 영문은 한글보다 문자당 토큰이 적다 → 문자 기준 부정형의 불리함이 토큰 기준에서는 줄어든다. **P3(−18.7%)는 토큰 기준 상한이다.** P2a·P2b(−62%대)는 격차가 이 정도로 뒤집히는 규모가 아니다.

**(3) 무처치 baseline이 이미 오염돼 있다.** 이 저장소 `CLAUDE.md`의 응답 규칙("결론부터, 서론·자평 금지")이 서브에이전트 시스템 프롬프트에 상수로 걸린다. 조건 B는 억제가 이미 일부 걸린 상태다 → **−62%/−69%는 하한이다.** 진짜 무처치 대비 절감은 API로만 잴 수 있다.

**기법**: [`techniques/positive-conciseness-instruction.md`](../techniques/positive-conciseness-instruction.md)

## 4. A1-H6 / A5-H2 — 검증 지시 제거 · **기각**

공식 문서가 "토큰 감소 + 품질 손실 없음"을 명시한 유일한 항목이고 라운드 1이 "가장 아까운 탈락"으로 기록했던 가설이다. **파일 기준으로는 반대 방향이 나왔다.**

| 지표 | B (검증 지시 없음) | V (검증 지시 있음) | 차이 |
|---|---|---|---|
| `L_file` | 2,425.0 | 2,272.7 | **+6.7%** (B가 더 길다) |
| `L_report` | 428.0 | 567.7 | **+32.6%** (V가 더 길다) |
| **총출력** (파일+보고) | 2,853.0 | 2,840.4 | **−0.44%** |
| `cov` | 6.0 | 6.0 | 0 |

사전등록 P1은 `L_file(B) < L_file(V)` 차이 >5%를 요구했다. 실측은 반대 부호 6.7% → **기각.** P1q(품질 무손실)는 충족했지만 판정 규칙이 `P1 ∧ P1q`이므로 채택되지 않는다.

### 왜 이렇게 됐나

검증 지시의 비용이 **파일이 아니라 대화로 갔다.** V 조건 3시행 모두 보고문에 6항목 대조표를 붙였고, 그중 2건은 자체 검증에서 실제 오류를 1건씩 찾아 고쳤다("버킷 소유 주체를 사용자로 썼다 → API 키로 정정"). 즉 검증 지시는 작동했지만, 그 작동의 산출물이 측정 대상 파일 밖에 쌓였다.

총출력이 −0.44%(동률)라는 것이 이 실험의 실제 결론이다: **검증 지시는 총 출력량을 바꾸지 않고 파일↔대화 사이로 재배분한다.** (이 합산은 사전등록된 지표가 아니라 사후 관측이다.)

### 이 기각이 말하지 않는 것

- 공식 문서의 주장이 틀렸다는 뜻이 **아니다.** 문서가 말하는 것은 코딩 에이전트의 과잉 검증 루프(추가 도구 호출·재읽기)이고, 이 실험은 산문 1건 작성이라 검증할 도구 호출 여지가 거의 없었다. **과제가 가설의 사정거리 밖이었을 가능성이 크다.**
- V의 표준편차 581.0은 조건 간 차이 152.3자보다 **크다.** 사전등록 규칙이 ±5% 동률 구간을 문자 기준으로만 정의했기 때문에 6.7%가 기각선을 넘었지만, 분산 대비로는 이 차이를 방향까지 확신할 근거가 약하다. **"제거해도 안 줄었다"까지가 이 데이터가 지지하는 최대치이고, "제거하면 늘어난다"는 주장은 하지 않는다.**
- 라운드 4에서 도구 호출이 실제로 발생하는 코딩 과제(`fixtures/task-a-bugfix`)로 재시험한다.

## 5. A1-H7 — 프롬프트 마크다운 제거 · **기각**

| 사전등록 예측 | 실측 | 결과 |
|---|---|---|
| P4 마크업 비율 `F < B` | −9.1% | 명목상 충족 |
| P5 길이 `F < B` | **+39.3%** | 기각 |

P5가 크게 반대로 갔다. 프롬프트에서 표·굵게·백틱을 없앴더니 산출물이 2,425자 → 3,377자로 **늘었다.** 3시행 모두 B 평균보다 길다.

### 계측 결함 — P4의 "충족"은 허수다

사전등록한 `markup` 지표는 마크다운 구조 문자(`#`·목록머리·`|`·`**`·백틱)만 센다. F 조건 산출물은 마크다운 대신 **ASCII 괘선**으로 제목을 그었다.

```
요청 제한(Rate Limit) 동작 설명서
================================

0. 큰 그림: 토큰 버킷이란
-------------------------
```

이 괘선은 지표에서 **0으로 계산됐다.** 실제 분량을 넣어 보정하면 부호가 뒤집힌다.

| 조건 | 마크다운 구조 문자 | ASCII 괘선 문자 | 합 | 전체 | 보정 구조 비율 |
|---|---|---|---|---|---|
| B | 43.3 | 0.0 | 43.3 | 2,425.0 | 0.0179 |
| **F** | 55.0 | **824.0** | 879.0 | 3,377.0 | **0.2603** |

보정 후 B 대비 F는 **+1,357%**다. 마크다운 헤딩 사용 횟수는 F 3시행 모두 0 — 즉 **모델은 프롬프트의 서식을 확실히 모방했다.** 마크다운을 안 쓴 것은 맞다. 문제는 대신 고른 방언이 더 비싸다는 것이다. `##`는 3자, `-------------------------`는 25자다.

그리고 F의 길이 초과분 952자 중 **824자(86.6%)가 이 괘선 문자다.** P4와 P5는 별개 현상이 아니라 하나의 현상이었다.

**판정 처리**: 사전등록 규칙대로라면 `P4 충족 ∧ P5 기각 → 부분 채택`이다. 그러나 P4의 충족은 지표가 824자를 0으로 센 결과이고, 그 결함은 하필 이 비교에서만 한쪽으로 작용한다. 지표를 고치면 P4도 반대 부호다. 따라서 **기각**으로 판정한다 — 사전등록 결과보다 **불리한 쪽으로** 정정하는 것이므로 사후 유리화가 아니다. 사전등록 명목 결과(부분 채택)도 여기 함께 남긴다.

### 얻은 것

가설은 틀렸지만 기전은 확인됐다: **모델은 프롬프트의 서식 방언을 따라간다.** 방향만 반대다. 절감을 원하면 프롬프트에서 마크다운을 빼는 게 아니라, **출력 서식을 명시적으로 지정**해야 한다(A1-H1이 실제로 한 일).

**계측기 수정 이월**: `score_r3.py`의 `markup_ratio`는 setext 제목(`===`/`---`)과 괘선 행을 세지 않는다. 라운드 4 전에 고친다. 이 라운드의 `markup` 수치는 **B/N/P/V 사이에서만** 유효하다(그쪽엔 괘선이 거의 없다).

## 6. 부수 관측

- **결정성은 파라미터 수준마다 다르다** (라운드 2 교훈 재확인). T2(추출)는 두 조건 모두 분산 0, T1(산문)은 표준편차 110~581. 같은 라운드 안에서 갈렸다.
- **V 조건의 자체 검증이 실제로 오류를 잡았다.** 3시행 중 2건이 "버킷 단위를 사용자로 썼다"는 내부 불일치를 스스로 발견해 고쳤다. `cov` 게이트로는 안 잡히는 종류의 오류다 — 커버리지 정규식은 항목 존재만 보고 서술 정합성은 안 본다. **품질 게이트가 검증 지시의 이득을 측정할 해상도가 없었다.**
- 피험자 2건(t08·t10)이 보고문에 "MCP 서버 미인증" 알림을 언급했다. 조건과 무관한 하네스 잡음이고 `L_report`에 각 1건씩 들어갔다(조건 N·P 각 1건). 절감 방향과 반대쪽 조건에 실렸으므로 결론을 흔들지 않는다.

## 7. 이 라운드가 만들지 못한 주장

사전등록 §7 그대로 유지. 추가로:

- A1-H7의 "서식 방언 교체" 기전은 n=3 산문 1종에서만 봤다. 다른 과제에서 ASCII 괘선이 아닌 다른 방언(예: 들여쓰기)으로 갈 수 있다.
- A1-H6 기각은 **산문 작성 과제에 한정**된다. 도구 호출이 발생하는 코딩 과제로 일반화하지 않는다.
- A2-H6의 항등식 `18(N+1)+50`은 8열 표에서 유도했다. 열 수가 달라지면 계수 18이 `2×(열수−1)+4`로 바뀐다 — 이 형태는 미검증이다.
