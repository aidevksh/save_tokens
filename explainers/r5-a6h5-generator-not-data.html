60행 대신 2줄

규칙이 명시된 데이터 60행을 나열하는 대신 그것을 만드는 코드로 내게 했습니다. 2,160자 → 102자, −95.3%. 실행해서 대조했더니 60행이 정확히 복원됐습니다. 단 데이터가 불규칙해지면 이 이득이 사라집니다.

시킨 일 — 샤드 배치표 60행(shard_id,host,port,weight)을 만들게 했습니다. 재료를 규칙적인 것(행이 인덱스의 함수)과 불규칙한 것(60행을 그대로 제시) 두 벌로 만들고, 각각 데이터로 내는 조건과 코드로 내는 조건을 돌렸습니다.

기준 (비교 대상) 짧아짐 = 이득 길어짐 = 손해모든 수치는 문자 수 (토큰 아님)
1

입력 — 모든 조건에 똑같이 준 것

규칙 조건에서는 데이터를 주지 않고 규칙만 줍니다. 두 조건이 받는 명세는 글자 하나까지 같고, 마지막 '할 일' 문단만 다릅니다.

프롬프트 (규칙적 재료 조건의 공통 부분)
아래 규칙으로 샤드 배치표 60행을 만듭니다.

- 행은 `shard_id,host,port,weight` 네 값을 쉼표로 이어 붙인 CSV 한 줄입니다. 헤더 줄은 없습니다.
- i 는 0부터 59까지입니다.
- shard_id 는 `shard-` 뒤에 i 를 세 자리로 0 채움 한 값입니다 (shard-000, shard-001, …).
- host 는 `node-` 뒤에 i 를 10으로 나눈 몫을 붙이고 `.example.com` 을 붙인 값입니다.
- port 는 7000 + i 입니다.
- weight 는 i 를 4로 나눈 나머지에 1을 더한 값입니다.
↑ 전문입니다. 불규칙 조건에서는 이 규칙 대신 60행을 그대로 실었습니다(2,105자).

생성 코드 4시행 전부 실행 결과가 기대 데이터와 일치했습니다. 짧아진 대신 틀린 것이 아닙니다. 다만 불규칙 조건의 두 시행은 1,373자와 2,118자로 갈렸습니다(표준편차 372).

복잡도가 낮은 데이터는 자기 자신보다 짧은 설명을 가집니다

콜모고로프 복잡도의 아이디어입니다 — 어떤 대상의 복잡도는 그것을 출력하는 가장 짧은 프로그램의 길이입니다. 1010101010…(1000번)은 "10을 500번 출력하라"로 줄어들고, 난수열은 줄어들지 않습니다.

규칙 조건의 60행은 전부 i의 함수입니다. 그래서 두 줄짜리 루프가 데이터 전체와 정보적으로 같습니다. 2,160자가 102자가 되는 것은 압축이 아니라 표현 층위를 바꾼 것입니다.

이 저장소의 다른 형식 기법(TSV, 접기, 코드북)은 전부 "같은 데이터를 다른 표기로" 였습니다. 이것만 데이터 대신 생성기를 냅니다.

불규칙한 데이터에 쓰면 도박이 됩니다

불규칙 재료에서 두 시행이 1,373자와 2,118자로 갈렸습니다. 두 번째는 60행을 삼중따옴표 문자열에 통째로 넣고 print 한 번 한 것이라 나열(2,105자)보다 길어졌습니다 — 데이터에 프로그램 껍데기만 얹은 꼴입니다.

조건 평균으로는 −17.1%지만, 이 조건에서 "코드로 내라"는 지시는 결과가 두 배로 갈립니다. 규칙이 명시돼 있을 때만 씁니다.

참고로 이 실험의 불규칙 재료도 shard_id 만은 인덱스의 함수였습니다. 완전 무작위 데이터에서는 역전이 확실할 것으로 보이나 재보지 않았습니다.

받는 쪽이 실행할 수 있어야 합니다

코드를 받은 쪽은 파이썬 실행 환경이 필요합니다. 이 비용은 재지 않았습니다. 사람이 눈으로 확인해야 하는 산출물이라면 쓸 수 없습니다.

실행 대조를 게이트로 걸지 않으면 이 기법은 측정 자체가 성립하지 않습니다. 짧아도 틀리면 의미가 없습니다. 이 실험은 4/4 통과했지만, 실제로 쓸 때도 같은 검증을 붙여야 합니다.

수치는 전부 글자 수이며 토큰이 아닙니다. 반복되는 CSV 행은 토크나이저가 이미 싸게 처리할 수 있어 실제 토큰 절감은 −95.3%보다 작을 수 있습니다.
